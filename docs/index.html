The methodology

A process that doesn't stop at “looks good.”

Use the full G0–G7 funnel on substantial tasks, or select a lighter workflow for a small change. Gates track evidence and can be reopened when source changes make earlier verification stale.

  1. 01

    Understand the system

    Inspect the repository, define the task, identify constraints and reproduce failures.

  2. 02

    Implement with discipline

    Plan narrow changes, use relevant specialist skills, and preserve existing behavior.

  3. 03

    Verify real outcomes

    Run tests and appropriate checks; record source fingerprints, logs and unresolved risks.

  4. 04

    Hand over the evidence

    Explain exactly what changed, which tests ran, what failed, and what remains unverified.

Clear about limitations

Verification is a practice, not a guarantee.

The included offline scanner is a limited heuristic—not a comprehensive security audit, dependency-CVE service, penetration test or proof that an app is secure. Framework tests don't prove autonomous performance across all six AI agents. Always inspect changes before deploying to production.
